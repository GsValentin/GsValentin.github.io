Intrusion Physique sous Windows & Sécurisation

Accès hors-ligne via Live-CD Linux, contournement de mot de passe local et protection par chiffrement

BTS SIO SISR • Bloc 3 • Cybersécurité
Cadre légal & déontologique : Les manipulations étudiées dans ce TP sont réalisées exclusivement en environnement isolé (machine virtuelle) dans un but pédagogique de compréhension des vulnérabilités physiques afin de déployer les contre-mesures adaptées[cite: 76].

1. La vulnérabilité de l'accès physique (Live-CD / Live-USB)

Un simple mot de passe de session Windows protège l'ouverture de session lorsque le système d'exploitation est démarré, mais ne chiffre pas le contenu du disque dur par défaut[cite: 76].

  • Démarrage sur un système externe (Live-DVD Ubuntu) : En amorçant la machine sur une image ISO Linux en mode Essayer Ubuntu, le système Windows installé sur le disque virtuel n'est pas actif et ses verrous logiciels (ACL NTFS) sont ignorés par l'environnement Live[cite: 76].
  • Conséquence : Il est possible de monter la partition Windows, de lire et de modifier librement les fichiers personnels (ex. C:\Users\...\Desktop\toto.txt) ou système sans connaître le mot de passe de session[cite: 76].

2. Contournement du mot de passe local Windows

L'accès en écriture à la partition système C:\Windows\System32\ depuis un support externe (ISO d'installation Windows ou Live-CD Linux) permet de réinitialiser le mot de passe d'un compte local administrateur[cite: 76] :

  • Technique de substitution d'utilitaire d'accessibilité (Utilman / Touches rémanentes) : Remplacer temporairement l'exécutable utilman.exe (ou sethc.exe) par cmd.exe permet, une fois revenu sur l'écran de connexion Windows, d'ouvrir une invite de commandes avec les privilèges maximums (NT AUTHORITY\SYSTEM) et de réinitialiser le mot de passe via la commande net user <utilisateur> <nouveau_mdp>.
  • Outils dédiés (ex. chntpw sous Linux) : Édition directe de la base SAM (Security Account Manager) dans C:\Windows\System32\config\SAM pour vider le mot de passe d'un compte local.

3. Contre-mesures indispensables pour sécuriser le poste

Pour empêcher un attaquant disposant d'un accès physique à la machine d'accéder aux données ou de modifier les fichiers système[cite: 76], il faut combiner plusieurs niveaux de défense :

Mesure de sécurité Mécanisme de protection Effet face à un Live-CD
Chiffrement intégral du disque (BitLocker) Chiffre l'intégralité de la partition système avec une clé liée à la puce TPM (et/ou un code PIN au démarrage). La partition est illisible et impossible à modifier sans la clé de récupération : bloque totalement la lecture et le remplacement de fichiers.
Mot de passe BIOS / UEFI + Verrouillage de l'ordre de boot Protège l'accès aux paramètres matériels (F2/F12) et interdit le démarrage sur USB ou CD/DVD externe. Empêche l'attaquant de lancer un Live-CD Ubuntu ou un support d'installation Windows.
Secure Boot (Démarrage sécurisé) Vérifie la signature cryptographique du chargeur d'amorçage (bootloader) avant le lancement de l'OS. Bloque l'exécution de supports d'amorçage non signés ou altérés.

4. Et sous Linux ou macOS ?

Le problème est identique sur n'importe quel système d'exploitation tant que le disque n'est pas chiffré : démarrer sur un Live-CD permet de monter la partition Linux (ext4) et de lire les fichiers de /home ou de réinitialiser le mot de passe root (via chroot et passwd)[cite: 76]. La protection repose là aussi sur le chiffrement complet du volume au niveau matériel/système : LUKS sous Linux et FileVault sous macOS.
