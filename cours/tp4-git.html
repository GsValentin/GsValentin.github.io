Git : Gestion de Versions Décentralisée

Cycle de vie d'un dépôt (Working Copy, Index, Repository), commits, historique et navigation temporelle

BTS SIO SISR • Bloc 1 / Développement • Versioning

1. Principe & Architecture de Git

Git est un logiciel libre de gestion de versions décentralisé créé par Linus Torvalds[cite: 78]. Contrairement aux systèmes centralisés, chaque utilisateur dispose d'une copie complète de l'historique du projet en local et peut travailler hors-ligne avant de synchroniser ses modifications[cite: 78].

Un projet Git s'articule autour de trois zones fondamentales[cite: 79] :

  • Working Copy (Répertoire de travail) : Vos fichiers réels visibles et modifiables sur le disque[cite: 78, 79].
  • Index (Staging Area) : Zone tampon temporaire où l'on prépare les fichiers avant de les valider[cite: 79].
  • Repository (Dépôt local .git) : La base de données contenant l'historique complet et immuable de tous les commits (identifiés par un hash SHA-1)[cite: 78, 79].

2. Workflow de base : Initialiser, Ajouter, Commiter

Action Commande Effet sur les zones Git
Créer un dépôt git init nom_dossier Initialise un nouveau dépôt vide (crée le dossier caché .git)[cite: 78].
Cloner un dépôt git clone <url> Télécharge localement un dépôt distant existant avec tout son historique[cite: 78, 81].
Vérifier l'état git status Affiche les fichiers modifiés, non suivis (untracked) ou prêts dans l'Index[cite: 79, 81].
Préparer (Index) git add <fichier> Envoie les modifications de la copie de travail vers l'Index (zone de transit)[cite: 79, 81].
Valider (Commit) git commit -m "Message" Enregistre définitivement l'état de l'Index dans l'historique du dépôt[cite: 79].
Comparer git diff / git diff --cached git diff compare Working Copy ↔ Index ; --cached compare Index ↔ dernier commit[cite: 79].

3. Historique, Annulation & Voyage dans le temps

  • Consulter l'historique : git log (ou git log --graph --pretty=short) affiche la chronologie des commits, leurs auteurs et leurs empreintes SHA-1[cite: 79, 80].
  • Retirer de l'Index sans perdre le travail : git reset <fichier> annule un git add et renvoie le fichier dans la copie de travail[cite: 79, 80].
  • Annuler les modifications locales : git checkout -- <fichier> restaure le fichier tel qu'il était au dernier commit (écrase les modifications non commitées)[cite: 80].
  • Voyager dans l'historique : git checkout <COMMIT_ID> bascule temporairement le dossier dans l'état d'un ancien commit (état detached HEAD)[cite: 80]. Pour revenir au présent, exécuter git checkout main (ou master)[cite: 80].
Synchronisation distante (GitHub) :
• git fetch origin : récupère les nouveautés du serveur sans toucher à vos fichiers[cite: 81].
• git pull origin main : télécharge et fusionne immédiatement les modifications distantes[cite: 81].
• git push : envoie vos commits locaux vers le dépôt distant.
